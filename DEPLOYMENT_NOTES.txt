NayaDost SAFE BUG FIX BUILD — 2026-09-14

1) Use this project root exactly as uploaded: package.json, server.js, public/index.html, public/icon-180.png, bot.py, render.yaml, etc.
2) Render uses a Starter web service with a 1 GB persistent disk mounted at /var/data.
3) DB_DIR=/var/data is set in render.yaml. User balances, pending mining, taps, referrals, tasks, wallet and payment records stay in SQLite.
4) DO NOT change the Render service to Free if you need balance persistence.
5) Mini App and API are same-origin: https://nayadost-3.onrender.com
6) Daily mining limit is exactly 5000 taps. The server and UI both use the same daily counter.
7) Mining goes into pending_mining; CLAIM moves it into balance.
8) TON Connect scripts are loaded before the wallet initialization code. The previous defer timing bug is removed.
9) Telegram channel tasks use a two-step flow: Join first, then tap Verify & Claim. Each Telegram task gets a new claim window every 2 hours.
10) Private Telegram channels require EARN_CHANNEL_CHAT_ID / OFFICIAL_CHANNEL_CHAT_ID in Render because an invite URL cannot be used as a Bot API chat ID.
11) Referral counts are reconciled from the actual referrer_code relationships on bootstrap.
12) Unknown /api routes return JSON 404 instead of the HTML app shell, preventing "invalid JSON (200)" caused by an HTML response.
13) Existing VIP miner/payment functionality from the stable build is preserved.
14) The old stable package.json and tonconnect-manifest.json are included with the new files.
15) Never put BOT_TOKEN, API keys, admin secrets or private keys in public/index.html.
