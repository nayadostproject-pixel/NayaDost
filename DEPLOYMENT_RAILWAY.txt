NayaDost Mining — Railway deployment

1. Push/replace the project files in the GitHub repository connected to Railway.
2. Railway uses the root Dockerfile, so this service runs Node.js/Express, not Python.
3. Add a Railway Volume and mount it at /data.
4. Set DB_DIR=/data.
5. Generate a public HTTPS domain in Railway Service Settings > Networking.
6. Set APP_URL=https://YOUR-RAILWAY-DOMAIN and APP_DOMAIN=YOUR-RAILWAY-DOMAIN.
7. Set TELEGRAM_BOT_TOKEN and the payment/admin secrets from .env.example.
8. Set PAYMENT_USDT_ADDRESS to the USDT-on-TON receiving owner address.
9. Set EARN_CHANNEL_CHAT_ID and OFFICIAL_CHANNEL_CHAT_ID if channel membership verification is enabled.
10. Set the Telegram bot WEB_APP_URL/API_BASE_URL to the new Railway URL.

Feature fixes in this build:
- Mining limit: 5000 taps/day, server enforced.
- Telegram tasks: Telegram membership only; no wallet verification required.
- Telegram tasks can be claimed again every 2 hours using a separate repeatable claim ledger.
- Direct referral count is based on actual referral relationships and does not wait for wallet verification.
- Unknown /api routes return JSON instead of the SPA HTML shell.
- VIP Pay opens the $25 USDT-on-TON deposit QR + deposit link immediately.
- VIP payment can still be paid from a connected TON wallet when available; blockchain confirmation remains server-side.
- SQLite is the authoritative source for balances, mining, referrals, tasks, wallets, deposits and withdrawals.
